# 0.2.19-r4 热修记录：调度探测 WaitGroup panic

- 执行时间：2026-11-01 23:43 – 2026-11-02 00:38 (CST)
- 目标：us-server
- 起因：r2 引入、r3 未修复的 `sync: negative WaitGroup counter` 崩溃，导致容器每 60–120 秒重启一次

## 1. 根因

`backend/internal/service/account_scheduler_degradation.go`

```go
runOne := func(account AccountSchedulerAccount) {
    defer wg.Done()        // ← 多余
    ...
}
for i := 0; i < accountSchedulerProbeWorkers; i++ {   // 4
    wg.Add(1)
    go func() {
        defer wg.Done()    // worker 自己已经 Done
        for account := range work {
            runOne(account) // → 再 Done 一次
        }
    }()
}
```

`wg.Add` 只按 worker 数（4）计数，但每个任务在 `runOne` 又额外 `Done` 一次。
**批次任务数超过 worker 数即计数为负**，`wg.Wait()` 后 panic。

引入提交 `2d10ec663 feat(account-scheduler): add degradation-aware scoring`（0.2.19-r2）。
这也解释了崩溃节奏：无 due 账号时完全正常，一旦待测账号 >4 就进入崩溃循环。

1. **止血（23:44）**：`account_scheduler_group_settings.degradation_enabled` 置 false（组 2/4/98），

   `RunScheduled` 每次读库，无需重启即生效。验证：75 秒内 Restarts 14 保持不变。

4. **激活**：updater operation `93faabd151e9df0a5bd3f44f7c849ce9`，prepare → ready（pending_migrations=[]），
   activate → completed（约 146 秒）。
5. **恢复开关**：组 2/4/98 的 `degradation_enabled` 恢复 true。
