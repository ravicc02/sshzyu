# 平台 Agent

Agent 负责持久化编排，通过 `handler/agent_platform.go` 复用平台模型路由、授权和计费。后端以 Linux amd64 镜像运行，不在服务器运行本地大模型。浏览器负责页面和动效，正式服务器不需要 Node 构建环境。

## 启用与升级

首次安装需要按正式数据库迁移流程应用 `250_agent_workspace.sql` 至 `257_agent_storage_maintenance_indexes.sql`。迁移由应用的数据库初始化路径执行；`AGENT_ENABLED=false` 不会跳过 SQL 迁移。生产和已有开发数据库的迁移需要单独授权。

这些 Agent 迁移尚未正式发布，源码按仓库要求使用 LF 行尾。早期本地实验数据库可能记录过 CRLF 文件校验值。切换实验后端前应先只读核对迁移台账；不要删除台账、跳过校验或自动改写历史 checksum。

配置变量：

| 变量 | 默认值与作用 |
| --- | --- |
| `AGENT_ENABLED` | 默认 false；true 时接受新任务并启动 4 个 worker |
| `AGENT_STORAGE_DIR` | 默认 `<pricing.data_dir>/agent`；必须位于私有持久卷 |
| `AGENT_RECONCILE_TIMEOUT_SECONDS` | 默认 120，范围 1～900；核对窗口不会因取消、重启或重试而延长 |
| `AGENT_STORAGE_MAX_BYTES` | 默认 6442450944，即全局 6 GiB；包含所有用户的文件、检查点和预留量 |
| `AGENT_MIN_FREE_DISK_BYTES` | 默认 8589934592，即 8 GiB；接纳新存储操作前检查所在文件系统水位 |

容量变量必须是正整数，非法配置会关闭接单，不会静默放开限制。单用户仍为 1 GiB。上述额度是资源保护，不是用户任务费用预算；旧预算字段仅兼容已有 schema，不能通过它扩大或缩小真人批准的任务范围。

调用并发保持既有行为：4 个 worker、每批默认 3 路生图。图片解码和大型终态响应物化共用一个局部内存处理槽，短时排队，不减少上游模型或生图请求的并发数。增加实例需要共享同一 Agent 文件存储并重新评估容量；本版生产配置建议保持单实例。

## 内存和文件生命周期

- SSE 写入器只保留未完成帧与已接受的终态证据，不再保存一份完整 SSE 原文；累计响应限制仍为 64 MiB，单图限制仍为 40 MiB。
- 检查点将 JSON 正文与 Base64 图片直接流式写入私有临时文件，完成后原子替换，不再构建整份大 JSON 的编码副本。已内嵌的图片不会再次保存一份 Base64。
- 原图下载先用有界缓冲校验所有权、过期状态和完整性，再从文件流式响应；不会为每个下载请求读取整张图片到内存。
- 私有缩略图接口为 `GET /api/v1/agent/assets/:asset_id/thumbnail`，限制最长边 896。缓存最多 128 项且合计最多 16 MiB，读取始终重新检查所属用户及原文件有效期。
- 前端靠近可见区域才请求缩略图；原图仅在预览、下载时加载。切换或关闭预览会释放旧原图 URL，取消不再需要的传输。旧后端未声明缩略图能力时保留兼容路径。
- 文件与检查点内容保留 24 小时；会话、最终输出、资产元数据和账单审计不会随文件一同删除。
- 定时物理清理与接单开关分离：已存在 Agent schema 时，即使关闭 `AGENT_ENABLED` 也会继续清理。每轮限 50 个文件、100 个检查点、1000 条终态任务的过期冗余过程事件。
- 模型流式进度最多每 750 ms 合并持久化一次。压缩终态任务超过 24 小时的冗余过程事件，保留终态事件、最终消息、最终步骤、操作状态和计费证据。
- SSE 重连回放最多读取 4 条、目标最多 512 KiB 未压缩 JSON；超大单条独立传输并继续分页，避免一次聚合 200 份完整快照。
- 启动检查点核算每批扫描 100 条，不将全部检查点清单加载到进程。核算失败停止接单，清理继续运行；`/agent/info` 返回是否接单和清理最近成功时间。

## 运维与计费

Agent 的真实模型和生图调用经过原有计费链，成功调用直接计入现有 usage_logs 的调用、Token 和费用聚合，不另加一笔费用。内部调用现在也经过原有运维错误采集通道，支持分组、模型、账号和稳定请求 ID 关联；仅授权探测和模型列表获取不算真实模型请求。

未知上游结果不会自动重新生图。先持久化接受的结果与确认费用，再做解码、保存或恢复；已确认收费的任务不会因为客户端断线而允许无条件重发。存储压力会在新操作发出前返回明确错误；已经持久化的响应可供后续核对恢复。

通用 `/health`、普通网关拨测与 Agent 任务健康需要分别检查。运维应关注：进程 RSS、容器 OOM、磁盘剩余空间、Agent 内容使用量、清理心跳、数据库增长，以及真实任务是否能从 queued 继续执行。

## 验证与发布边界

示例配置位于 `deploy/agent-production.override.example.yml`，是待容量验证的配置样例，不会自动作用于本地或生产。`GOMEMLIMIT` 是 Go 运行时软目标，不能替代容器硬上限，硬上限也不能证明全站任意流量下都不会 OOM。

测试使用独立 PostgreSQL schema：`AGENT_TEST_DATABASE_URL` 为每个用例创建独立 agent_test_* 命名空间，`AGENT_HTTP_TEST_DATABASE_URL` 对应 agent_http_test。不要把现有用户数据库交给会创建测试 schema 的脚本。

```text
go test -race ./internal/agent
go test -tags=unit ./internal/handler -run TestAgent
go test ./internal/agent -run '^$' -bench BenchmarkAgentOutcomeCheckpoint -benchmem
```

真实供应商的流式、工具调用、取消、图像响应及单次计费仍需正式灰度验收。模拟上游、合成大图测试和本地浏览器通过不代表已经完成生产压力验证。Excel/Office 解析和 PPTX 导出不属于当前能力。
