## 部署方式

本地构建镜像 → 压缩传输（44.7MB，md5 校验一致）→ 服务器 `docker load` → compose 切 tag →
仅重建 sub2api 容器。**全程未在服务器上构建**（2 核 4G，此前构建曾导致整机内存耗尽）。

## 回滚方式

1. 代码：`git checkout <旧分支>`，或恢复备份 compose
2. 镜像：服务器保留 `local/sub2api-batch:0.2.4-r2`
3. compose：
   ```bash
   cp /root/sub2api-backup-pre-0.2.5-r1-20260917-165356/docker-compose.yml /opt/sub2api-deploy/docker-compose.yml
   cd /opt/sub2api-deploy && docker compose up -d sub2api
   ```
4. 数据库（如需）：
   ```bash
   docker exec -i sub2api-postgres pg_restore -U sub2api -d sub2api --clean \
     < /root/sub2api-backup-pre-0.2.5-r1-20260917-165356/db.dump
   ```

备份目录：`/root/sub2api-backup-pre-0.2.5-r1-20260917-165356/`
（`docker-compose.yml`、`config.yaml` 712B、`db.dump` 188M / 1213 条目已验证可读）

## 已知事项

1. **service 包 1 个测试失败**：`TestOllamaProbeCallback_StaleLongDoesNotOverrideNewShort`
   已在**纯 v0.2.5**（不含自有补丁）上复现同样失败 → 官方既有问题，非本次引入。
2. **本机前端构建的环境坑**：`VITEST_MAX_FORKS=4` 在 32 核机器上导致 vitest 报
   `minThreads/maxThreads must not conflict`。本机构建前需 `unset VITEST_MAX_FORKS`；
   Docker 内构建不受影响（已实测通过）。
3. **`openai_ws` 连接池默认系数 1.0 → 5.0**（官方 v0.2.5 有意变更）。线上 config.yaml
   未显式设置该项，已采用新默认值。
4. **上游账号 403（非代码问题）**：本地验证时发现账号 205（阿里云 MaaS 某 workspace）
   返回上游 403，账号 157（并行科技）对 `GLM-5.3-Flash` 报 "team not allowed to access model"，
   网关 failover 正常（157 失败后切 91 成功）。线上 205 早已停止调度并移出分组 65。
5. **前端仍为定制版**：v0.2.5 新增的管理界面（OpenCode 平台管理、站点类型开关、批量操作按钮）
   在定制前端上不可见。如需这些界面，需将 v0.2.5 前端改动合并进定制分支（另立任务）。
