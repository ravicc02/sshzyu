# 2026-09-24 本地抽奖功能开发记录

> 本次改动**仅在本地**,未连接 hk-server、未修改线上任何服务/数据库、未触碰 mpay。

## 功能

个人中心「幸运抽奖」(本地 MVP):

- 正常账号(active、未删除)首次进入抽奖体系自动获得 1 次免费抽奖;
- 基线后累计余额消耗达 **$5** 解锁第 2 次,此后每新增 **$10** 解锁 1 次(阈值 $5/$15/$25/…);
- 余额消耗口径 = `SUM(usage_logs.actual_cost) WHERE billing_type = 0`(钱包余额计费),从用户进入抽奖体系的时刻(baseline_at)起算,**不追溯历史消耗**;
- 金额比较在服务层换算为整数美分,避免浮点误差;
- 中奖结果完全由服务端生成(crypto/rand 加权随机),库存原子扣减不超发;
- 发放状态机: pending → granted / failed(可重试),balance_bonus 类型走 `AdjustBalance` 原子发放;
- 流水 `(user_id, idempotency_key)` 唯一约束,重试同 key 返回已有结果,不重复扣次数。

## 2026-09-28 追加:线上发布后侧边栏无抽奖的事故与修复(缓存穿透机制固化)

> 现象:线上发布 `20260928-ui-r1` 后,用户线上侧边栏仍是旧版(无「幸运抽奖」),而本地正常。

**根因(三层叠加,与浏览器缓存无关的部分占主导):**

1. 线上 nginx 的 `location ^~ /assets/` root 是 `/opt/sshzyu-ui/shared`,而 `shared/assets` 是 switch-release.sh 用 `cp -rn`(no-clobber)维护的**累积库**——同名文件**永不被新 release 覆盖**;
2. `shared/assets/fw-cachebust.js` 因此停留在 2026-09-12 旧版,内容写死旧 entry `index-C7MNXNPX.js`(r8 时代)→ 所有线上用户实际加载的一直是 **9 月 10 日 r8 的 UI**,r10(09-22)与 r1(09-28)两次发布对用户浏览器从未生效;
3. 叠加 immutable 旧缓存:老用户浏览器里已有的 fw-cachebust 副本带一年 immutable,服务器改 no-cache 也不会使其回源。

**修复(已全部生效):**

| 层 | 动作 |
| --- | --- |
| nginx | `location = /assets/fw-cachebust.js` 的 root 从 `shared` 改为 `current`——引导文件随每次 switch-release 自动更新,不再被累积库的 no-clobber 卡住(备份 `/tmp/sub2api.bak-fwcb-root-20260928`) |
| 缓存穿透 | 线上与本地 index.html 的 fw-cachebust 引用统一加 `?v=20260928r1` 版本参数——URL 变化使带旧 immutable 缓存的浏览器强制回源 |
| 脚本固化 | `sshzyu-local-site/build/build-online-equivalent.mjs`:第 3 步改为写入 `?v=<entry-hash>`(每次构建 entry hash 必变→版本参数必变);entry 解析增加从 fw-cachebust.js 回退解析的健壮性修复。注意 sshzyu-local-site 非 git 仓库,改动直接落盘 |
| 产物对照 | 验证链:index.html(no-cache)→ `fw-cachebust.js?v=` (200, no-cache, →D51hLg1W)→ entry 200 → AppLayout-B8nXwxrQ 含 `path:"/lottery"` 且无 hideInSimpleMode |

**教训:**发布验证必须核对「fw-cachebust → entry → AppLayout」整条引导链的内容一致性,不能只验证 release 目录里有产物、URL 返回 200(SPA fallback 会掩盖路由缺失)。
