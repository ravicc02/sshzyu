## 根因链

1. **前置**：上游智谱渠道 key 403 → 渠道不可用 → 503（00:32 起）。
2. **放大**：单一下游脚本无退避重试 → 流量洪峰（占 79%）。
3. **崩溃**：03:42 宿主层强制重启（非本机 OOM/panic），导致 Redis AOF 尾部 1966 字节损坏。
4. **持续 503 的直接根因**：`sub2api-redis` 反复崩溃 → Docker DNS 解析不到 `redis` 服务名 → 调度/限流失效。nginx 与 sub2api 应用本身始终正常。

## 处置动作（已获用户授权）

```bash
cd /opt/sub2api-deploy
docker compose stop redis
# 备份（55M，root 700）
cp -a redis_data/appendonlydir/. /root/redis-aof-backup-20260830/
# 修复（仅截断损坏尾部：ok_up_to=41826386, diff=1966）
printf "y\n" | docker run --rm -i --entrypoint redis-check-aof \
  -v /opt/sub2api-deploy/redis_data/appendonlydir:/data redis:8-alpine \
  --fix /data/appendonly.aof.554.incr.aof
docker compose start redis
```

注意：redis 日志提示的 `--fix <filename.manifest>` 在 redis:8-alpine 镜像下需显式 `--entrypoint redis-check-aof` 才能正确传参；manifest 实际文件名为 `appendonly.aof.manifest`（seq 554）。数据损失仅崩溃瞬间未完整写入的 1966 字节。
