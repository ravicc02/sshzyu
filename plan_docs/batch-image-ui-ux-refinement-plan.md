# 批量生图 UI / UX 与交互完善方案

> 日期：2026-10-02
>
> 状态：已实施，待部署 migration 与线上发布
>
> 关联方案：`plan_docs/batch-image-llm-to-config-plan.md`
> 目标页面：`frontend/src/views/user/BatchImageGuideView.vue`

## 1. 背景与目标

现有 OpenAI 批量生图已经跑通需求转换、配置卡、多规格分组提交、统一参考图、任务轮询、结果预览和 ZIP 合并，但页面仍暴露了较多技术实现细节：

- 同一次用户提交被同时显示为一个“提交集合”和多个后端子批次，主列表信息重复。
- 创建入口标题限定为 OpenAI，但通用批量生图仍需识别 Gemini Key 并保留原 Gemini 创建流程。
- OpenAI 输入尚未转换时，右侧配置区域完全消失，双栏布局失衡。
- “保持一致性”、统一参考图及逐卡参考图仍使用原生复选框和文件输入，视觉层级和页面既有组件不一致。

本轮目标是让用户始终围绕“一个批量任务”操作，把后端子批次降级为详情中的执行信息，并统一 OpenAI / Gemini 的创建入口、空状态、参考图控件及任务详情。

## 2. 产品原则

1. **一个用户动作对应一个总任务。** 用户不需要理解多规格为何产生多个后端 batch。
2. **平台由 Key 决定。** 创建入口保持通用，选择 OpenAI 或 Gemini Key 后进入对应流程。
3. **布局在状态变化前后保持稳定。** 未转换、转换成功、校验失败和提交中不能造成大幅跳动。
4. **技术信息按需展开。** 子批次 ID、分组规格和单批费用放入“执行批次”视图。
5. **沿用现有设计系统。** 使用现有按钮、输入框、状态徽章、Toggle、图标和颜色，不引入新的视觉语言。
6. **不修改 Gemini provider 行为。** Gemini 后端协议、参数、调度、计费和结果处理保持现状。

## 3. 总任务模型

### 3.1 主列表只显示总任务

删除列表上方独立的“提交集合”卡片，不再把同一次提交的各个子批次作为平级主任务重复展示。

建议主列表结构：

```text
+--------------------------------------------------------------------------------+
| 任务名称              平台 / 模型          状态       结果     费用      操作   |
+--------------------------------------------------------------------------------+
| 终端命令三图          OpenAI               已完成     3 / 3    $0.67     查看   |
| 2 个执行批次          gpt-image-2.5-sunburst                                |
+--------------------------------------------------------------------------------+
```

总任务聚合字段：

- 总任务 ID / collection ID
- 任务名称
- API Key 与平台
- 模型摘要；多模型时显示“多个模型”
- 子批次数量
- 总 item 数、成功数、失败数、取消数
- 聚合状态
- 总冻结金额与实际费用
- 下载状态
- 创建、提交、完成时间

### 3.2 聚合状态规则

| 子批次状态 | 总任务状态 |
|---|---|
| 仍有前端分组未提交 | 提交中 |
| 任一子批次 uploading / submitted / running / indexing / settling | 进行中 |
| 全部完成且无失败 | 已完成 |
| 有成功且有失败 | 部分成功 |
| 全部失败 | 失败 |
| 全部取消 | 已取消 |
| 结果均已删除 | 结果已删除 |

### 3.3 稳定的总任务标识

当前 `collectionFingerprints` 仅保存在浏览器 `localStorage`。这能支持同浏览器刷新恢复，但清理缓存或换设备后会退化为多个子任务，不能作为长期总任务关系的唯一来源。

建议增加一个轻量通用字段 `collection_id`：

- OpenAI 多规格分组提交时，各子批次携带同一个 `collection_id`。
- 单批 OpenAI、Gemini 和历史任务缺少该字段时，以自身 batch ID 作为总任务 ID。
- 列表和详情 API 返回 `collection_id`，前端据此聚合。
- 不改变 Gemini provider 请求、参数和处理流程。
- 不复用 `parent_batch_id`；该字段继续只表示失败重试父子关系。
- `localStorage` 继续保存未确认提交、幂等键和前端草稿，不再承担长期任务关系。

如本轮希望严格限制为纯前端改造，可以暂时沿用 `localStorage` 聚合，但必须接受换浏览器后无法恢复总任务关系的限制。推荐采用 `collection_id` 方案。

## 4. 总任务详情

点击主列表中的总任务后，只打开一个总详情，不再先选集合再分别打开子任务。

```text
+--------------------------------------------------------------------------------+
| 终端命令三图                                                [已完成]           |
| OpenAI · gpt-image-2.5-sunburst · 2 个执行批次                                  |
|--------------------------------------------------------------------------------|
| 成功 3        失败 0        总数 3        总费用 $0.67                         |
|--------------------------------------------------------------------------------|
| [结果 3] [执行批次 2]                                                         |
|                                                                                |
| 结果页：缩略图 / Prompt / 规格 / 状态 / 错误 / 单图操作                       |
|                                                                                |
|                                        [导出成功图片] [重试失败项]             |
+--------------------------------------------------------------------------------+
```

### 4.1 “结果”页签

- 合并加载所有子批次 item，并按原配置卡顺序排序。
- 展示缩略图、完整 Prompt、分辨率、宽高比、模型、Custom ID、状态和错误。
- 默认仍按需加载缩略图，避免列表自动拉取全部图片。
- 失败项明确显示来源、错误码和修复建议。
- 已由重试子任务补成功的旧失败项保持现有去重规则。

### 4.2 “执行批次”页签

- 展示后端 batch ID、规格、模型、item 数、状态、冻结金额、实际费用和时间。
- 子批次 ID 可复制，但不作为页面首要信息。
- 单个异常批次可以单独查看、重试或下载诊断信息。

### 4.3 总任务操作

- `导出成功图片`：等待全部子批次终态，下载并合并可用 ZIP。
- `重试失败项`：只处理失败 item，不重复提交成功项。
- `取消未完成任务`：列出将取消的活动子批次数量，并沿用当前计费提醒。
- ZIP 自动下载未启动时保留显式“保存 ZIP”链接。
- 删除总任务时，列出包含的子批次数量；继续采用软删除语义。

## 5. OpenAI / Gemini 创建入口

### 5.1 通用标题

- 页面主按钮：`创建批量生图任务`
- 弹窗标题：`创建批量生图任务`
- Key 占位：`请选择批量生图 API Key`

不再出现标题写 OpenAI、Key 提示却写 OpenAI 或 Gemini 的冲突。

### 5.2 Key 识别

Key 下拉使用当前 `batchImageApiKeys`，继续识别：

- `group.platform === 'openai'`
- `group.platform === 'gemini'`
- 已启用批量生图权限
- OpenAI 额外要求普通生图权限

选项中显示平台标识、Key 名称和分组名称，例如：

```text
[OpenAI] batch-e2e-account77 · 生图测试
[Gemini] gemini-production · 111
```

### 5.3 平台分支

选择 Key 后按平台渲染对应创建流程：

- **OpenAI**：保留现有“需求输入 → 转换 → 配置卡 → 多规格分组提交”流程。
- **Gemini**：恢复改造前已有的模型、尺寸、比例、输出格式、Prompt 列表、生成张数和参考图表单。
- Gemini 继续调用原有批量接口和 provider，不修改 Gemini 后端。
- 切换平台前如存在已编辑草稿，提示会清空或切换当前草稿；未确认则保持原 Key。
- 历史 OpenAI 和 Gemini 任务继续使用其原 Key 查询、下载、重试和删除。

## 6. OpenAI 创建区布局

### 6.1 右侧配置框始终显示

未转换时也渲染固定的右侧配置面板：

```text
+------------------------------------+  +------------------------------------+
| 需求输入                           |  | 配置草稿                  待转换   |
|                                    |  |                                    |
| [输入框]                           |  |          尚未生成配置              |
|                                    |  |                                    |
| [参考图设置]                       |  |                                    |
| [转换]                             |  | [提交并开始生成 - 禁用]             |
+------------------------------------+  +------------------------------------+
```

转换后仅替换面板内部内容，整体宽度、高度和提交按钮位置保持稳定。

### 6.2 右侧状态

| 状态 | 面板表现 |
|---|---|
| 空输入 | 空面板，状态“待输入” |
| 有输入未转换 | 空面板，状态“待转换” |
| 转换中 | 保留面板尺寸，显示轻量加载状态 |
| 转换失败 | 面板显示错误摘要，不生成半成品卡片 |
| 转换成功 | 显示配置卡和数量 |
| 输入变更 | 卡片保留，状态“需要重新转换”，禁止提交 |
| 配置错误 | 错误卡展开或标记，禁止提交 |
| 提交中 | 所有编辑控件锁定，显示分组提交进度 |

提交按钮固定在右侧面板底部。禁用时保留按钮，不隐藏，状态通过按钮和面板状态共同表达。

### 6.3 响应式

- 桌面端使用约 5:7 的双栏比例，让配置卡获得略多空间。
- 窄屏改为输入区在上、配置区在下。
- 两个区域都使用稳定的 `min-height`，不依赖内容撑开。
- 只有参数矩阵可横向滚动；错误信息和提交操作不可被挤出屏幕。

## 7. 参考图交互重做

### 7.1 统一入口

将当前“保持一致性”改为“统一参考图”，使用项目已有 `Toggle`，放入一个稳定的“参考图设置”区域：

```text
参考图设置
统一参考图                                                    [关闭]
每张配置可以使用不同参考图
```

开启后：

```text
参考图设置
统一参考图                                                    [开启]
所有配置使用同一张参考图

+------------------------------------------------------------------+
| 上传图片                                                         |
| PNG / JPEG / WebP，最大 10 MB                                   |
+------------------------------------------------------------------+
```

### 7.2 上传控件

- 隐藏原生文件输入，使用现有按钮和上传图标触发文件选择器。
- 空状态使用固定高度虚线区域，支持点击和拖放。
- 读取中显示文件名和进度状态，不改变区域尺寸。
- 成功后显示缩略图、文件名、大小，以及图标式“替换”“移除”操作。
- 错误在上传区内部显示，不在区域外散落提示文字。
- 提供清晰的 hover、focus、disabled、loading、error 状态。

### 7.3 逐卡参考图

统一参考图关闭时，每张展开配置卡显示紧凑的参考图行：

```text
参考图（可选）  [上传图片]
```

上传后显示缩略图、文件名、替换和移除操作。不要展示浏览器原生文件输入。

统一参考图开启时：

- 锁定逐卡上传入口。
- 卡片显示“使用统一参考图”和小缩略图。
- 已选择的逐卡图片继续保存在草稿中，但不提交。
- 关闭统一参考图后恢复原逐卡图片。

### 7.4 模型提示

- 只有当前 Key 的真实模型列表包含 `gpt-image-2.5-sunburst` 时，才显示“推荐模型：gpt-image-2.5-sunburst”。
- 去掉当前文案中的前导 `-`。
- 不自动切换模型。
- 模型不支持参考图时在选择模型后立即禁用上传和提交，不静默退化为文生图。

## 8. 视觉规范

- 沿用现有 `input`、`btn`、`badge`、`Toggle` 和 `Icon`。
- 面板与配置卡圆角不超过 8px。
- 使用 1px 边框和轻量中性色背景，不增加宽阴影。
- 避免卡片套卡片；输入区、配置区是两个主面板，配置 item 才使用卡片。
- 主色只用于主要操作、焦点和当前状态。
- 上传、空态、加载和错误状态使用稳定尺寸，避免跳动。
- 中英文文案同步；按钮文案表达实际副作用。
- 保留键盘操作、可见焦点、`role="switch"`、错误 `role="alert"` 和状态 `role="status"`。

## 9. 兼容与迁移

- 历史任务没有 `collection_id` 时按单任务展示。
- 现有 `collectionFingerprints` 历史记录可在首次加载时映射为临时总任务，待 API 返回稳定 collection ID 后更新。
- 未确认提交和幂等恢复继续保留；恢复入口移动到创建弹窗中的独立恢复区域。
- Gemini 历史任务和新任务都视为一个总任务、一个执行批次。
- 失败重试产生的 `parent_batch_id` 子任务归入原总任务结果页，并保持成功图片去重。
- 不清理现有任务、结果、ZIP、日志或本地恢复记录。

## 11. 验收用例

1. OpenAI 三张配置分成两个规格组，主列表只显示一个总任务，详情显示两个执行批次和三条结果。
2. 刷新页面后总任务关系、总状态、总费用和结果顺序不丢失。
3. Key 下拉同时显示合规 OpenAI 与 Gemini Key；选择 Gemini 后展示原 Gemini 创建表单。
4. Gemini 提交请求、后端 provider 和结果处理与改造前一致。
5. OpenAI 输入为空、待转换、转换错误、转换成功和过期状态下，右侧配置面板始终保持稳定。
6. 未上传统一参考图时禁止提交；上传后每个 OpenAI item 都携带同一图片。
7. 关闭统一参考图后恢复各卡此前选择的独立参考图。
8. 不支持参考图的模型不能静默退化为无参考图请求。
9. 总详情可以加载所有子批次结果，并只导出成功图片；失败项进入错误清单。
10. 重试失败项不会重复提交已经成功的图片。
11. 桌面和窄屏下不存在横向溢出、控件重叠或底部操作不可见。
12. 相关前端测试、类型检查、生产构建和后端批量任务回归通过。

## 12. 决策项

本轮已采用以下方案：

1. **推荐：增加通用 `collection_id`。** 这是稳定维护总任务的必要条件，不改变 Gemini provider 行为。
2. 主列表只显示总任务；子批次仅在总详情的“执行批次”页签出现。
3. 创建入口恢复为 OpenAI / Gemini 通用入口，OpenAI 使用新流程，Gemini 使用原流程。
4. “保持一致性”重命名为更明确的“统一参考图”。
5. 参数矩阵继续默认折叠，避免挤占主要输入与配置空间。

## 13. 实施结果（2026-10-02）

- 增加通用 `collection_id`、任务规格快照字段和 migration `246_batch_image_collection_id.sql`；旧任务按 batch ID 展示，旧浏览器记录可通过 `collectionFingerprints` 兼容聚合。
- 主列表按总任务聚合，同一次 OpenAI 多规格提交只显示一行；总详情增加“结果”和“执行批次”页签。
- 创建入口恢复为 OpenAI / Gemini 通用入口；OpenAI 使用需求转换流程，Gemini 使用独立组件恢复原批量表单和原后端协议。
- OpenAI 右侧配置面板常驻，未转换时展示“尚未生成配置”，提交按钮保持固定位置。
- “保持一致性”改为“统一参考图”Toggle；统一图与逐卡图都使用一致的上传面板，支持点击和拖放，切换模式保留逐卡图片。
- 统一参考图推荐文案只在当前 Key 返回 `gpt-image-2.5-sunburst` 时显示。
- 相关前端 60 项测试、类型检查、定向 ESLint、生产构建以及 Go 批量任务定向回归通过。
- 本地浏览器验证通过：历史两个技术批次聚合为一个总任务，三张结果按 Custom ID 排序，执行批次展示真实历史规格；OpenAI / Gemini 创建分支和 390×844 窄屏布局正常。
- 全量前端测试当前为 284 个文件通过、68 个文件失败；失败集中在本次未修改的 CustomPage、Subscriptions、Pagination 等既有测试，不属于本任务回归。
- 未执行本地或线上 migration，未部署服务器；按仓库规则，数据库变更需要在后续部署步骤中单独执行和验证。
