## 子代理报告（原文摘要）

1. 产出 5 个文件：`剧本.md`、`视觉设定.md`、`分镜.md`、`图片提示词.md`、`视频提示词.md`；未建 `设定集/`。
2. 需要自行判断的地方：
   - `图片提示词.md` 定位是人物/场景/道具设定图，但任务要 3 条 SHOT 首帧；只能写成 `IMG-EP001-001~003` 并挂到分镜，代价是与分镜「首帧提示词」正文重复。
   - 视觉设定字段两处文档不一致：示例用「状态变化」，assets 说明用「本集状态」。
   - 骨架只给镜头未给场次，自行拆成 SC001 走廊、SC002 轿厢。
   - VO 的全集秒数没有字段可放，写入分镜「声音」行。
   - 为挂服装连戏锁单建「造型」条目，本集实际无换装。
3. `creator_markdown_check.py` 的 `--partial` 与全量均返回 `OK`；子代理另在临时副本删除关键字段，脚本能正确报错，说明检查器不是空转。
4. 自评卡点：首帧在 `IMG` 与 `分镜` 双写最别扭；检查器不覆盖制作形态、时代背景、目的、声音等字段，`OK` 不等于全格式合规。

## 卡点清单

| # | 严重度 | 卡点 | 证据 | 影响 | 建议 |
| --- | --- | --- | --- | --- | --- |
| K1 | **P0 阻断** | 没有可用的视频生产链路 | `short-drama-produce` 自述「尚无已实现的 SSHZYU 任务单 adapter」；SSHZYU `/v1/videos` → `HTTP 404: Videos API is not supported for this platform`；宿主供应商 → `403 Seedance requires an OpenAI or composite group` | 套件目前无法完成真实视频生成；只能做静帧动态漫或外部手工补片 | 实现 SSHZYU 任务单 adapter，或在文档中把「视频生产」明确标为未接通，并给出静帧降级路径 |
| K2 | P1 | CLI 默认走失效本地代理，错误表现为平台不可达 | `HTTPS_PROXY=127.0.0.1:7890`，`/health` 000；直连 200 | 用户会误判为服务故障，浪费排查时间 | `doctor` 增加只读连通性探测；CLI 在连接失败时提示检查代理或给出 `NO_PROXY` 提示（不改系统配置） |
| K3 | P0 | 视频模型不在 `/models` 仍继续提交 | `/models` 无 `kind=video`；CLI 只打印 `MODEL WARNING` 后提交，返回 404 | 失败发生在付费提交阶段，错误信息不指向根因 | 提交前把「无视频模型」当作硬失败并说明账号未开通；或明确文档要求先 `models` 验证 |
| K4 | P2 | 请求尺寸与实际尺寸不一致 | 请求 1024×1792，实际 948×1659，`partial=1`、`exit=2` | 用户不知道是否需要重试；剪辑需额外缩放 | 输出中说明「模型对齐尺寸」而不是只标 partial；或在参数矩阵写明该模型的可选尺寸 |
| K5 | P1 | 首帧提示词双写 | 分镜有「首帧提示词」，图片提示词又有 3 条 `IMG-*` 首帧；子代理明确称「最别扭的妥协」 | 两处正文漂移后无法判断哪份是权威；维护成本翻倍 | 明确首帧提示词归 `分镜.md` 或 `图片提示词.md` 之一；另一处只放引用编号 |
| K6 | P1 | `package` 语义与直觉不符 | SKILL 写「打包创作者文档与有效交付文件」；实际只含 6 个 `.md`，成片需 `export` | 用户以为交付包含成片，实际没有 | 在 SKILL 明确 `package`=文本/JSON，媒体交付走 `export` |
| K7 | P1 | 视觉设定字段名不一致 | 示例「状态变化」vs assets 说明「本集状态」 | 子代理需要猜；不同 agent 会写出不同字段 | 统一字段名，示例与说明同源 |
| K8 | P2 | VO 全集秒数无字段 | 子代理只能写进分镜「声音」行 | 不同集/不同 agent 记录位置不一致，剪辑阶段难以机器读取 | 在分镜或剧本索引中定义 VO 时间字段 |
| K9 | P2 | `pacing` 未配置但目标时长已设置 | `status` 输出：`target_seconds_per_episode is set but format.pacing has no usable rates` | 写剧本阶段无法把台词换算成秒数，15 秒目标缺少依据 | `init` 后提示配置 pacing，或按语言给安全默认值并在文档写明 |
| K10 | P3 | 相邻段运镜速度不一致 | `check` 提醒 1.6%/s vs 1.2%/s，相差 33% | 成片切点可能有轻微顿挫 | 剪辑单模板给同速默认值，或 `check` 提供自动统一建议 |
| K11 | P2 | 字幕标点被替换、长句拆行 | `字幕.srt`：「门开了，里面没有人」→「门开了　里面没有人」；首句拆成两条 | 与「逐字取自剧本」的表述有偏差；情绪停顿被改 | 文档说明标点规范化规则，或保留标点 |

## 结论

- **可跑通的部分**：项目初始化 → 五份创作文档 → 图片生成 → 静帧剪辑 → 字幕/音效 → 渲染验收 → 导出交付。

- **最该先修的**：K1（视频 adapter/降级说明）、K3（视频模型预检）、K5（首帧双写）。这三项直接决定下一轮实跑能否从「静帧动态漫」升级为「真实短剧生成」。
